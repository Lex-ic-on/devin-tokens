# devin-tokens

Aggregate [Devin CLI](https://devin.ai) token usage from local transcript files.

Reads `~/.local/share/devin/cli/transcripts/*.json` (auto-saved by Devin CLI) and prints daily / per-session summaries. No special flags or export steps needed.

## Install

```sh
# With uv (recommended)
uv tool install git+https://github.com/Lex-ic-on/devin-tokens.git

# Or from a local clone
git clone https://github.com/Lex-ic-on/devin-tokens.git
cd devin-tokens
uv tool install -e .      # editable — picks up local changes

# Also works with pip / pipx
pip install git+https://github.com/Lex-ic-on/devin-tokens.git
```

Requires Python 3.10+. No external dependencies (stdlib only).

## Usage

```sh
devin-tokens                        # last 14 days, daily summary
devin-tokens --days 7               # last 7 days
devin-tokens --since 2026-06-01     # from a specific date
devin-tokens --until 2026-06-30     # up to a specific date
devin-tokens --all                  # all sessions
devin-tokens --list                 # one row per (session, day)
devin-tokens --session rough-neon   # per-step detail for one session
```

## Token columns

| Column | Meaning |
|---|---|
| `input` | Net prompt tokens sent to the model (`prompt_tokens - cached_tokens`) |
| `output` | Completion tokens generated by the model |
| `cached` | Tokens served from cache (reduced cost); `---` for ACP sessions |

## Aggregation basis

Token usage is aggregated at the **step** level. Each agent step in a
transcript carries its own `metrics` block (`prompt_tokens`,
`completion_tokens`, `cached_tokens`, and `cache_creation_input_tokens`
under `metrics.extra`) plus a timestamp.

- **Daily view** groups steps by their own timestamp (local timezone), so a
  single session that spans multiple days contributes to each of those days.
- **`sessions` column** counts distinct sessions that had at least one step
  on that day — the same session may appear on multiple days.
- **`--list`** shows one row per `(session, day)` pair.
- **`--session <id>`** prints a per-step breakdown (input, output, cached,
  cache creation) with the session total.

ACP sessions (Hermes-via-ACP, carrying `_acp_metadata`) are shown on a
separate `ACP` row per day. The ACP protocol does not report cache counts,
so their `cached` column shows `---`.
